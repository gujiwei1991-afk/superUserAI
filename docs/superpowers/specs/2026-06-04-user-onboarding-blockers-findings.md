# 诊断：普通用户"进门"卡点（真机验证发现）

- 日期：2026-06-04
- 来源：升级雷达真机验证时意外发现，PMAgent 升级雷达代码已上线但消息一次都没走到它
- 状态：待设计修复（用户已决定转修）

## 背景

真机测试「升级雷达」时，连续多条消息全被前置路由/意图层拦截，PMAgent 一次都没真正介入。暴露出 3 类与「普通用户提需求不专业」直接同源的卡点——比升级雷达更靠前、更致命。升级雷达是"PMAgent 进门后更聪明"，但用户连门都进不去 / 进错门。

## 卡点 A：状态机太死——已完成项目无法承接新改动

- **现象**：激活项目状态为「已完成」（或其它非 `drafting`）时，群里用大白话提新改动（"增加一列规格"），意图判为 `chat`，但被 `_handle_chat_internal` 拦截，回 "当前项目状态为「已完成」，不在需求沟通阶段，请发送 #状态 查看进度"。
- **复现**：激活项目 [12] 已完成 → 发"装备确认中，增加一列规格…" → intent=chat → 冷拒。
- **根因**：`backend/app/services/message_handler.py:205` —— `_handle_chat_internal` 仅当 `project.status == DRAFTING` 才放行到 `pm_agent.chat`，其余状态一律拦截。
- **用户视角**：「项目完成了想再加点东西？没门。」普通用户不懂"完成了要发 #新需求 重开"。
- **初步修复方向（含产品决策，待定）**：已完成/已部署项目收到新改动诉求时，识别为"新一轮需求"，顺势引导或自动开新需求会话，而不是冷拒。与卡点 B 的 `#新需求` 体验联动。

## 卡点 B：命令不友好——`#新需求` 缺仓库名静默降级 + 报无关错

- **现象**：`#新需求 <直接写需求>`（没带仓库名，或仓库名与需求间无空格）→ 命令解析失败 → **静默降级成 `chat`** → 撞上卡点 A 的状态拦截 → 报"项目已完成"这种与真实原因（缺仓库名）完全无关的错。
- **复现**：`#新需求 装备确认中，增加一列规格…`（中文无空格）→ 降级 chat → 已完成项目 → "不在需求沟通阶段"。
- **根因**：`backend/app/gateway/command_parser.py:23-25` —— `remainder.split(maxsplit=1)` 得不到 2 段就 `return Command(type="chat", ...)`，丢失"用户想新建需求但格式错"的信息；错误提示由后续 chat 路径给出，驴唇不对马嘴。
- **用户视角**：「我明明发的新需求，咋说项目已完成？」
- **初步修复方向**：`#新需求` 解析失败时返回明确的格式提示（如"`#新需求` 要带上仓库名：`#新需求 <仓库> <需求>`"），可附可用仓库列表；不要静默降级成 chat。

## 卡点 C：意图误判——需求文本含"确认"等词被当成确认，提前生成 PRD

- **现象**：在 `drafting` 项目里补充需求的长文本，只要含"确认/通过/可以"等子串（如"装备**确认**中"），就被判成 `confirm`，直接走 `generate_prd`，把还很单薄的对话强行出成 PRD，`drafting → reviewing`。
- **复现**：drafting 项目 [13]，发"装备确认中，增加一列规格。头盔：夏季、冬季；送餐箱：30L/45L/62L；衣服：L~5XL" → intent=confirm → 生成半成品 PRD（PRD 自己都标注"需求方尚未回答澄清问题"）。
- **根因**：`backend/app/services/group_intent.py`
  - `_CONFIRM_WORDS`（第 39-57 行）用 `any(kw in text ...)` **子串匹配**，"确认" 命中 "装备确认中…"（第 120-124 行 CONFIRM 候选判定）。
  - LLM 二次验证 `_verify_confirm_with_llm`（gpt-4.1-mini）对"明显是补充需求的长文本"鲁棒性不足，误判 yes。
- **用户视角**：「我在补充需求，咋就给我出方案了？」
- **初步修复方向**：收紧确认判定——仅当整条消息近似一句独立的确认语才进 CONFIRM 候选（如长度阈值 / 确认词需为消息主体而非长需求中的子串）；并/或强化 LLM 验证 prompt，明确"长需求描述即便含'确认'字样也不是确认指令"。

## 优先级与范围（待与用户确认）

3 类相对独立，可各自走 spec→plan→实现：
- **C（意图误判）**：最接近纯 bug、风险低、见效快，且后果严重（误生成 PRD、污染流程）。建议优先。
- **B（命令降级报错）**：方向明确，纯改善错误提示，低风险。
- **A（状态机承接新改动）**：含产品决策（已完成项目如何承接新需求），最需讨论，建议放后。
